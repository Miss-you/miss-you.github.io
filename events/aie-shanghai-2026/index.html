AIE 上海 2026

AI Engineer 上海 2026（2026-11-05 至 11-06）逐场记录。

AI Engineer 大会 2026 年 11 月 5 日至 6 日在上海举行。这里每场一页，记讲者的主要论断、关键原话、例子与数字，以及没听清或需要核对的地方。

S 编号的场次据作者现场录音整理。M、B 编号的场次（主舞台部分场次和 11-05 下午的 AI 应用分会场）据现场外部录音整理，未与本人录音对照。

官方录像由 AI Engineer 在 YouTube 陆续放出，见 AI Engineer Shanghai 播放列表。截至 2026-11-10 只放出 1 场（S02），已放出的场次在页首「视频」一栏给出链接。

分格内容#

C1 模型与后训练 · X 解释#

  • 有些能力做了就有、没做就没有：模型在某个任务上表现好，是因为专门做了数据和评测，不能只等泛化。 — S07
  • 只奖励答对，模型也会顺带学会什么时候该停：一道多跳题从 150 次搜索、130 万 token 降到 3 次搜索、7 万 token。 — S03
  • agent 里很多 LLM 调用只是在做小决策，没必要逐 token 生成；一次前向给出答案和置信度就够。 — S28

C1 模型与后训练 · S 结构#

  • 做搜索 agent 的后训练，RL 数据集比训练框架和环境更重要：题源选中等热度的网页，按 pass@8 丢掉全对和全错的题。 — S03
  • 为长程 agent 选模型，看四项工程能力：激活参数（单步成本）、长上下文、原生视觉、工具调用。 — S07
  • 决策模型的做法：把分类任务改成统一模板做 LoRA 微调、去掉因果掩码；置信度校准用温度缩放，不需要强化学习。 — S28
  • 端侧的内存墙从“总参数”变成“活跃参数加预加载”：35B MoE 只加载活跃专家，再预测下一步要用的专家，在 iPhone 上用约 2G 内存跑。 — S09
  • ⚔️ 自己训还是不训。 Langfuse 预测最好的团队下一步会用改进循环里攒下的标签造 RL 环境、训自己的开源模型；Cookiy 坚持不做后训练，认为未来一年 harness 还有大量空间；Nowledge 试过把团队上下文训进参数，9 个实验只有 3 个有收益，转而把团队知识做成 harness 直接用的上下文层。分歧在现阶段应用公司的改进空间是在权重里，还是在 harness 里。 — S01 · B06 · S36

C1 模型与后训练 · E 事件#

  • You.com 用约 5000 条 SFT 轨迹加 1500 个 RL 任务、8 小时 RL，让开源 30B 模型的 BrowseComp 从 37 分升到约 45.5 分。 — S03
  • AutoArk 发布 150B 端侧 MoE 多模态模型预览，最低 18–24G 内存，瞄准本机跑编码 agent。 — S09
  • Liquid AI 上周做出两个端侧决策模型，一个纯文本、一个带视觉。 — S28

C2 基础设施 · S 结构#

  • 推理优化每一层都必要但都不充分：单 GPU 上的技术本质是少算、少搬数据、把硬件用满，再叠上集群层的调度；讲者引社区数据说，全部叠起来比不做优化的基线高出几个数量级，所以要做全栈。 — S04
  • 没人计划过 AI infra：数据库被 agent 构建者的需求推着长出 trace 分析、状态快照和文件层，价值是让团队把注意力留给 agent 的下一次迭代。 — S14
  • 从按 token 付费切到自建部署有一个可算的临界点：月 token 量 = 部署月成本 ÷ 每百万 token 有效单价；自建以后仍要在网关上保留按 token 付费做兜底。 — S15
  • 智能硬件全靠云端 API 会越卖越赔；端侧做意图分流、只把开放问答送上云，耳机案例省掉 92% 以上的 token 成本。 — S09
  • agent 沙箱要的是短命但有状态，和 K8s 为长期运行、出错自愈的服务设计的目标相反；在 K8s 上硬做有状态，坑在外挂存储。 — S10
  • RL 后训练卡在沙箱调度上，基础设施故障还会变成错误的 reward 信号混进训练。 — S16
  • LLM 网关的 HTTP 200 不等于成功：同一会话要粘在一家 provider，同一模型只暴露两家都支持的功能，跨区域要身份全局、推理本地。 — M03
  • 对照：自建还是外采。 Techcombank 算出用量过线就该从按 token 付费转为自租 GPU 部署，Optiver 因为协议翻译会弄坏东西，最后自建只含所需功能的精简网关；Daytona 主张沙箱别自己造，DataHub 主张底层设施外采、只把业务定义握在自己手里。四家讲的是不同组件，没有正面交锋：用量算得清、现成方案出过错的倾向自建，安全面大、团队会换人的倾向外采；后两家本身就卖这类服务。 — S15 · M03 · S10 · B08

C2 基础设施 · E 事件#

  • Google 开源 RL 沙箱方案，讲者自报百万级同时并发、首条指令 P99 1 秒内、12 分钟填满 100 万个沙箱，没给对照测试。 — S16
  • Daytona 自测：同样负载耗时少 36%，波峰型负载成本低 2.7 倍（厂商自测）。 — S10
  • Optiver 把提示词日志改为直写各区 S3、鉴权用本地副本后，鉴权延迟从 2 秒降到 20 毫秒。 — M03
  • Techcombank 的例子里临界点约 830 亿 token/月，过线后估计能省 30–50%。 — S15

C3 上下文、记忆与数据 · X 解释#

  • 上下文工程先问上下文是什么形状：私有格式 agent 写得出来，却没法在里面推理；换成它最擅长的代码，模型变强，产品就跟着变强。 — S19
  • 企业数据的老问题没变，只是犯错的主体从人换成了 agent：人会在数字进 PPT 前复核，agent 不会，而且规模更大、更自信。 — B08

C3 上下文、记忆与数据 · S 结构#

  • agent 需要专门给机器用的搜索引擎；搜索网页的 AI agent 已经多过人。 — S03
  • 个人 agent 的检索预算：先搜索读高亮，不够才开浏览器，每一步只拿下一步决策需要的最少 token；记忆要区分是谁的偏好、影响哪个计划。 — S12
  • 企业数据和 agent 之间要有一层上下文层：采集、自动提炼、专家验证、再分发，每条上下文带可信度等级。 — B08
  • 数据 agent 的瓶颈不在写 SQL，在数字能不能信：本体建在现有语义层上，再用编译器把规范编成确定性 SQL、拒绝错误查询。 — B10
  • 网页转 Markdown 不是最后一步：把整页原文喂给主流模型，每千个页面的成本已和广告每千次浏览的收入同一量级，还得再压缩。 — S37
  • 数据涨十倍以内靠单机优化，涨百倍千倍只能重构架构：容量假设从有限换成无限，围绕对象存储做热温冷三层，每层成本差一个数量级，任何一层都能直接查。 — S13
  • 像珍惜内存一样珍惜 context：放进去的每样东西都要算信噪比，问一句不放能不能达到同样效果。 — S25
  • 对照：记忆的存与用。 Zilliz 把 agent 的记忆看作下季度的训练数据，同一份数据既服务线上召回、也供离线挖掘；Nowledge 同样把原始轨迹全存成 episodic memory，但给 agent 用时要管脉络和衰减，知识衰减是 feature，做得差的记忆不如没有。两边讲的是不同层：底层留全，交给 agent 的上下文要会忘。 — S13 · S36

C3 上下文、记忆与数据 · E 事件#

  • Exa 的索引已不只是网页：新闻 15 分钟入索引、300 万档播客全文，还为个人 agent 新加了 2 亿多个地点。 — S12
  • 经 Jina Reader 处理后，网页 token 数中位数约 4.5K–5K，呈对数正态分布；原始 HTML 约 30K。 — S37
  • DataHub 的客户数字：Miro 的 agent 准确率约从 50% 到 90%。 — B08
  • Zilliz：客户里最大的单一业务，数据条目每年涨一个数量级，今年已到千亿条。 — S13

C4 Harness 与 Agent 架构 · X 解释#

  • harness 工程是实验科学：先写假设和验证方式，再让 AI 执行实验；能扩大实验数量，就能扩大迭代效率。 — S25
  • ⚔️ harness 该加还是该减。 StepFun 认为模型能力要真正用进工作流，harness 得补上保存目标和进度、挑选上下文、写验收条件、云端持续执行这些环节；MiniMax 认为模型变强后，提示词、subagent、todo/plan 都该拿评测逐项检验、能删就删。两边都留下了验证，也都要跨上下文接上进度；分歧在进度和拆分该由 harness 管（StepFun 用任务树记进度，subagent 只回结论），还是已经可以交给模型自己（MiniMax 让模型把任务写进本地文件交接，克制开 subagent）。 — S07 · S25

C4 Harness 与 Agent 架构 · S 结构#

  • agent 架构绕了一圈回到“模型加工具循环”，正在收敛到 coding agent 的样子；Langfuse 推荐把 agent 循环放在后端 worker 里，沙箱只是它按需调用的一个工具。 — S01
  • 云端 harness 是脑，管计划、上下文和选工具；本地电脑和远端 sandbox 是手。 — S07
  • harness 要决定四件事：模型看到什么、能做什么、怎么持续、怎么验证，其中验证最重要；新功能进 harness 前先交评测流程。 — S25
  • 讲者预测：agent 有了独立身份，会不经事先编排地互相协作，人只在审批点出现。 — M02
  • 管到第 500 个 agent，难点从构建转到运营、治理和优化：底层模型一更新、知识库一变，已经没有作者可问。 — B03
  • 对照：两种“拆 agent”。 MiniMax 说最近的 benchmark 显示多开 subagent 常常只是白耗 token，主张克制开启；Cookiy 的实时访谈最后走通的，是把判断、动作、回复拆成三类子 agent 级联。两者拆的不是一回事：前者是 coding 任务里分派子任务，后者是实时对话里把一次回复拆成流水线，为的是压延迟、防串信息。 — S25 · B06

C4 Harness 与 Agent 架构 · E 事件#

  • MiniMax 举 Claude Code 的几次调整：砍掉大部分系统提示词，承认单个强 agent 胜过多 subagent，先后去掉 todo 和 plan mode；推测下一个被去掉的是 /goal。 — S25
  • MiniMax Code 围绕前缀缓存和 token 效率的做法：工具放进 CLI 按需发现、用代码脚本批量调工具（PTC）、长命令自动转后台。 — S25
  • Cookiy 把 8000 字的中文 system prompt 砍到约 1/3，更快也更好；最笨的提速办法是同一请求并发调多次、取最快的。 — B06

C5 评估与验证 · X 解释#

  • 速度上来以后，瓶颈从生成移到 proof：工程师要从 intent engineering 走到 proof engineering，先把可验证的结果定义好，再让 agent 爬坡。 — S08
  • 写东西变便宜以后没人读得过来，所以不再检查产出本身，改为检查“检查者”。 — S22
  • 讲者预测改进循环会交给后台 agent 常驻跑，人只保留“质量”：定义什么算好、信哪些反馈信号、决定发不发。 — S01

C5 评估与验证 · S 结构#

  • Arena 评 agent 用随机对照实验：自己做一个通用 agent 产品，每个会话随机分配底层模型，再从真实轨迹里挖成功率、用户褒贬、纠偏程度等信号。 — S05
  • ⚔️ 通用榜单还能不能指导选模型。 Arena 认为静态题库会被刷，真实流量上的随机对照能给出可比的排名，同时建议按自己的成本和耗时在帕累托曲线上取舍；Harvey 认为别人的 context 和 harness 跟你不同，选模型只信自己 PR 上的回放；Agoda 发现同一个上下文工具换个仓库，结果就反过来；NUS 实测公开基准的错误率搬到自家音频上差 4 到 20 倍。分歧在通用排名能在多大程度上迁移到你的任务上。 — S05 · B02 · B07 · S23
  • 能写成确定性检查的就别交给 LLM：Data4Life 先跑测试，让 agent 截图、由 LLM 解读只做兜底；Meta 的验证智能体把构建、安装、登录写死以省 token，只让 LLM 把任务翻译成 CLI 调用；Daily 的语音对话没有确定答案，才让 LLM 当 judge 和模拟用户，人只审 judge 的标准。 — S22 · B09 · B05
  • agent 写的测试要再检验：一个组件覆盖率近 90%，变异测试只抓到不到 15%；有旧系统时，拿它当 oracle 跑真实样本。 — B09
  • 手机上的验证智能体光靠截图不够：要让 app 可观测、提供语义化操作，编码 agent 才能自测，CI 才能对每个变更跑验证。 — B05
  • agent 的产量上来以后，工厂速度取决于 CI：main 上关掉 CI 改成定时跑，再按影响范围做 adaptive testing。 — S08
  • 做了评测才发现，要改的常常不是模型和 harness，而是喂给模型的数据和流程里的小 bug。 — B02
  • 判断一次改动是否真的变好，要从同一个保存下来的现场开分支比较；只看 trace 不够，trace 只记录发生过什么。 — S14

C5 评估与验证 · E 事件#

  • Agent Arena 排名：美国前沿实验室领先，中国开源权重模型在第二梯队，但在性能-成本帕累托前沿上占了好几个位置。 — S05
  • Harvey 的内部实验：code review 上 DeepSeek V4.1 Flash 接近 Opus；修 CI 各模型质量差不多，差在耗时；整次实验约 7 小时、约 7000 美元。 — B02
  • Meta 的验证智能体靠扫自己的失败记录改进，一个月内有结论的验证比例从约 10% 升到约 55%。 — B05
  • NUS：从实时切段到整段录音，转写准确率从 62% 升到 82%，指定语言就补回 11 个点。 — S23
  • Cookiy 用几千条历史坏案例（精确到某场访谈的第几分第几秒）做 benchmark。 — B06

C6 组织与工作方式 · X 解释#

  • 自动化越多，人的决策越关键：自动接单 bot 几天就积下几十个没人审、没人定优先级的 PR；注意力是不可再生资源，常规决策要沉淀成 skill 和 memory。 — S11
  • AI native 团队有大量“Dark Office”产出，其中半闭环的自我改进已经跑起来，卡点在人的验证环节。 — S36
  • 这一轮变化的核心原因是 AI 独立做长程任务的能力：讲者说周围很多工程师已经不再手写代码，也读不过来 AI 写的代码。 — S17

C6 组织与工作方式 · S 结构#

  • Mono 解决“AI 看不全上下文”，任务公开解决“人看不全上下文”：全公司的代码、知识、内部工具进一个仓库，每个人的 agent 任务全公司可见、可加入。 — S11
  • 为了让更多人参与 AI-native 研发：技术架构改成精简内核加插件，组织按事分人，产品和设计也直接提 PR。 — S11
  • 工程师在变成工厂管理者：用 harness 造 harness，一个人并行跑几百个 agent。 — S08
  • 原型变快以后，人管验证和决定，开发和执行交给模型。 — S17
  • 大集团做不了 AI native 式的快速颠覆，能做的是先把几百个流程梳理进台账，让组织行为变成模型能用的数据。 — S21
  • 整条链路好比 1000 件事，AI 做掉 800 件，人只管四步：定交付要求、审带报价的达人名单、审脚本和终稿、复盘数据。 — B12

C6 组织与工作方式 · E 事件#

  • 一个人约 4 天、约 3000 元 token 做出一个可玩的游戏；一段视频一周内被社区做成可玩游戏。 — S17
  • Manus 讲者称，产品和设计直接提 PR 以来，没有因代码质量出过线上事故（没给观察期）。 — S11

C7 产品、设计与人 · X 解释#

  • 答案完整不代表我想过：被完整答案盖住的，是还没来得及形成的问题。 — S02
  • AGI 是最强的解码器，编码清晰的“显性大陆”会被吞没；垂直 AI 该去一部分编码清楚、四周是隐性知识的“群岛”。 — S20
  • 企业级 AI 的护城河在没有 API 的地方：词、没沉淀的数据、老设备、人；语义不统一时，模型越强，错得越漂亮。 — S21
  • ⚔️ 省时间还是花时间。 YouMind 说现有 Personal Agent 都在替人解决烦恼、满足欲望，省下的时间并不会花在想做的事上，所以要转向创作；圆桌上的投资人则认为帮人省时间的 personal agent 天花板有限，让需求扩张、帮人消耗时间的产品才做得大。分歧在“好产品”的尺子：一边看人有没有变好，一边看需求能不能扩张。Ryo Lu 站在使用者一侧补了一句：省下的时间不必重新填满。 — S02 · B01 · S24

C8 安全、权限与 Agent 经济 · X 解释#

C8 安全、权限与 Agent 经济 · S 结构#

  • 给 agent 独立身份是为了最小权限：权限在身份层由管理员按 agent 类别授予，agent 无论写 shell 还是写 Python 都越不过去。 — M02
  • 运行时意图裁判要本地跑、低延迟、看得到调用前的上下文；约 4 亿参数的判别类小模型除一个外准确率在 91%–93%，生成式小模型只有 70%；低置信要转给人，阈值逐个模型定。 — S33
  • agent 代人花钱，现有基础设施在三处挡住它：网站反爬、银行风控、用户不知道该授权什么；做法是卡不直接给 agent，给带范围和时效的 token，先每笔确认，再放开小额预算。 — B04
  • 品牌不愿被降格成 API，这就是主权；agent 经济需要各自保有主权的 agent 互相交换意图，而不是一个中心化的超级 agent 来分派。 — S29
  • 讲者的设想：沿用早期互联网的广告模式，让 agent 复述一段广告口播，或替别人做可自动验证的公开任务，来换免费访问。 — S37
  • ⚔️ agent 该不该按次付费。 Visa 拿开发者让 agent 通宵干活当实验场景（讲者承认是小众场景），单笔几分钱几块钱的数字服务不能每次叫醒人确认，所以要做小额支付；Jina 不看好 agent 按请求给网站付费（价格锚定就高、全球南方付不起），只同意访问控制要放在网关。两边讲的不全是一回事：Visa 管 agent 替人买东西怎么付，Jina 管 agent 读网页怎么计价；交叉处在于付费内容该按交易收钱，还是沿用广告换免费。 — B04 · S37

Physical AI · X 解释#

  • 按“它做什么”给世界模型分类（渲染、模拟、规划），再看领域、尺度与分辨率、覆盖度；世界模型是抽象推理和感知/行动之间的接口。 — S18
  • 硬件跟不上模型每周一次的迭代，所以硬件不该追模型，而该做成可预测的稳定接口：动作模型能预测，反馈模型能信。 — S32
  • 具身落地的关键是获取一个新能力的成本；力觉是操作的第一性输入。 — S31
  • 只看图像看不全物理状态：接触力、滑动、有没有抓稳都看不见，任务要等物理结果验证过才算完成。 — S26

Physical AI · S 结构#

  • 上层通用 agent 做 System 2，下层各领域模型做 System 1：World Labs 从世界模型的角色推出这种组织方式，未来不远的下一代家庭机器人也这样分。 — S18 · S34
  • ⚔️ 数据从哪来。 Noematrix 靠人类穿戴的无本体采集，后训练也不用遥操作；未来不远在第一人称数据之外，让机器人在真实家庭里的执行数据自动回流成下一代模型的训练数据；VAST 让程序管世界状态、模型管画面，造可交互的世界，并试着从真实演示里生成机器人数据的视觉变体（对机器人学习有没有用还要测）；数耀量生的自我改进循环只用真实数据、不经过仿真。四家没有互相回应，是四条路线的取舍：采集规模和与真机分布一致，更看重哪一头。 — S31 · S34 · S27 · S30
  • 能描述清楚的交给 agent 写代码，只能认出来、说不清的细节交给模型学。 — S27
  • 高斯分布表示不了多峰动作；讲者主张用玻尔兹曼能量地形表示，把求最低能量点交给光量子相干伊辛机。 — S30
  • 工业机器人的安全监督要独立于模型，用 PLC 或人工写的安全策略兜底。 — S26
  • 机器人数据采集一次、加工无数次，要的是构建系统，不只是存储。 — S35
  • 机器人数据表要让“加一列”几乎零开销、cell 带状态，用户写一个 Python 函数绑到列上，系统做增量计算。 — S35
  • 部件选型为可建模性让路：弃谐波减速器、用行星减速器，靠好建模的传动和执行器模型估力，不加关节力矩传感器。 — S32
