1. 能力从哪来：基模垂直补课与小数据 RLVR 配方#

  • 有些能力做了就有、没做就没有，不能干等泛化：阶跃星辰为解决代码 Bug 修复与重构自建自定义仓库/语言的 codebench（专家评测中约七成认为能自主完成复杂 coding ⚠️ 未给基线），后训练数据流程优化使准确率从 53.3% 升至 60%（⚠️ 未说明具体任务），并于 6 月发起“美育计划”先灌领域知识再训审美判断，专设 model product 与 product engineer 挖掘前沿场景塞进训练管线。 — S07
  • 小数据 RLVR 训搜索 Agent：中等热度网页 + pass@8 筛题，不加效率奖励工具调用骤降 95%：You.com 指出 RL 数据集比训练框架更重要。热门网页已被预训练背下（模型直接从权重掏答案不学调工具），冷门网页多垃圾，必须用覆盖数千亿网页的 Web Graph 切取几千个中等热度（medium popularity）网站出题，再用基座模型跑 pass@8 只保留答对 1–7 次的题（丢掉全对和全错）。仅用 5,000 条拒绝采样 SFT 轨迹 + 1,500 个 RL 任务 + 8 小时纯 RLVR（GRPO，零人工标注），开源 30B 模型在 BrowseComp 上从 37 分升至 45.45 分（+22%，其中 SFT 约 +3 分、RL 约 +5.5 分）；最关键的是未设任何效率奖励，但模型学会验证答案真伪后找对即停，一道多跳并购题从后训练前的 313 次工具调用（150 次搜索 + 118 次抓取）、130 万 token 且答错，降到 7 次工具调用（3 次搜索 + 1 次抓取）、7 万多 token 且答对（⚠️ 效率对比为单题案例，8 小时未披露卡数）。 — S03
  • ⚔️ 路线交锋：应用团队自己训还是不训（进权重 vs 留 Harness）：
    • 主张训权重：Langfuse 预测顶尖团队下一步会把改进循环攒下的带标签失败轨迹变成 Task + Verifier，自建 RL 环境训饱和开源模型（S01）；Baseten 强调在自有任务上微调是为了不把最值钱的客户信号（customer signal）白送给闭源模型厂（S04）。
    • 主张留 Harness：Nowledge Labs 与康奈尔研究者合作，尝试把动态团队上下文训进模型参数，9 个实验场景只有 3 个有正收益，反而是将团队知识编译成 Harness Adapter 直接喂给 Harness 全面胜出（S36）；Cookiy Labs 将 8,000 字冲突中文 System Prompt 砍到约 1/3 就更快更好（⚠️ 未给量化数字），坚持未来一年内绝不碰后训练（唯一例外是改模型性格，B06）。
    • 判断边界：有客观自动 Verifier 的静态工具本能或高频分类适合小数据 RLVR/LoRA；随时间高频演进的团队脉络与缺乏客观评判标准的早期产品，必须留在 Harness。

2. 模型怎么选与怎么拆：长程四指标、一次前向决策模型与端侧 35B MoE#

  • 长程 Agent 主力模型看四项工程指标：当任务拉长到几千步（如单张 H100 做 Kernel 优化持续迭代 22 小时、Pokemon 实验跑 3,000 多轮 / 耗 600 万 token、业界长程任务达 26–48 小时），单步开销会被乘上几千倍，选型必须同看：① 激活参数（如旗舰模型每 token 激活 27B）、② 1M 长上下文（实践证明仅在容纳代码、长文档、任务记录三类场景值得用满）、③ 原生视觉（看 UI 截图/渲染结果做自我验证必需品）、④ 工具调用稳定性。 — S07
  • 把高频小判断从“生成”里剥离，做成端侧一次前向决策模型：Agent 循环里大量调用只需回答 yes/no、score、choice，没必要逐 token 生成。Liquid AI 用三步将小模型改造成 Decision Models：① 把分类任务转为统一模板做 LoRA 微调（实测在消除选项位置偏差与负面偏好上优于全参数微调）；② 去掉 decoder 因果掩码（Lift the Causal Mask）改为双向注意力；③ 用温度缩放（Temperature Scaling）校准置信度，完全不需要强化学习（RL）。一次前向传播即可给出答案与把握度（如设定低于 90% 阈值直接弃答 ⚠️ 90% 为举例），已训出纯文本与带视觉两个端侧小模型（⚠️ 疑为 sub-billion 量级，因录音质量差待核）。 — S28
  • 端侧内存墙突破：iPhone 16 Pro 用 2G 内存跑 35B MoE + 预览 150B 端侧多模态 MoE：AutoArk 按算力将硬件切为三档（耳机/眼镜跑 0.1B 打包进 EvaSDK 并提供一行命令装进 Claude Code 的 agent skill；手机跑 35B MoE；笔记本/座舱预览占 18–24G 内存、prefill >1000 tok/s、decode >100 tok/s 的 150B MoE 多模态模型 ⚠️ 厂商自报）。手机端破内存墙的核心是只把 3%–10% 活跃专家留在 2G 内存里，单独预训练一个轻量模块在当前 token 推理时实时预测后续几个 token 所需专家，从 SSD 后台异步预取进内存。 — S09

3. 推理集群、多区域网关与算力经济账#

  • 全栈推理：单机少算少搬，跨云集群靠 KV Cache 亲和路由：单 GPU 上的 Prefill-Decode（PD）分离、chunked prefill、量化与投机解码本质是“少算、少搬数据、把硬件喂饱”；到了生产级跨云集群，路由不仅看物理距离和容量，**必须看 KV Cache 匹配度（把请求发往已缓存匹配长前缀的节点）**并配多级存储卸载，才能跑出 99.99%（四个 9） 可靠性（相比裸跑基线提升几个数量级）。 — S04
  • 多区域网关减法工程：LLM 请求强有状态，HTTP 200 不等于成功：Optiver 管理跨 4 大洲数据中心、日均 300 万次请求（22 个模型占 95% 流量）。踩坑某流行开源网关后发现：① 协议互译会静默丢掉 Anthropic 的加密 thinking block（⚠️ 口述将加密签名与内容摘要混同），当次返回 HTTP 200，下一轮却因缺失思维链被迫从头重算导致延迟和账单双爆；② 容灾四铁律：首包前才做 Failover（流中切厂重算更慢）、同一会话严格粘在单 Provider（防破一折前缀缓存致成本翻 2–3 倍）、同模型 ID 只暴露两家都支持的功能（交集原则）、平时固定分 10% 流量给备份通道演练；③ 身份全局、推理本地、计费最终一致：早期把 Prompt 日志写进跨洋主库导致每天传 200GB、Postgres 膨胀到 4TB、鉴权慢达 2 秒；改为日志直写本地 S3 + 鉴权本地只读副本 + 计费异步最终一致后，鉴权延迟从 2 秒骤降至 20 毫秒（-99% ⚠️ 未给统计分位数），最终放弃协议翻译自建薄网关，并借全链路分布式 Tracing 揪出慢在 3 分钟的 MCP 工具调用而非 17 秒的模型推理。 — M03
  • 🔍 对照：企业与硬件的三种算账公式（抠省 92% vs 830 亿临界点自建 vs 5 倍并发冗余）：
    1. 买断制硬件防“越卖越赔”（省 92%+）：100 万台智能硬件 × 日均 20 次交互全调云端 API，年成本高达 10 亿元；韶音 AI 运动耳机在端侧做 3A→VAD→ASR→轻量 NLP 意图分流，高频切歌/查心率全程在本地闭环，仅开放问答上云，省掉 92% 以上云端 Token 成本。 — S09
    2. 企业平台自租 GPU 临界点公式（省 30%–50%）：Techcombank 全组织紧盯唯一北极星指标**“每百万 token 有效混合单价”（全员追捧 Opus 会使其指数级攀升）。从按量付费切自租 GPU 的临界点为：月临界 Token 量 = 自租集群月固定成本 ($166K, 16张 B200) ÷ 有效混合单价 ($2/M) = 830 亿 token/月。过线切自建预计省 30%–50%（如 3,000 亿 token/月从 50 万降至 20 万美元 ⚠️ 口述数字略对不上），但网关必须保留同模型 Pay-per-Token 做波峰兜底（约 10% 触发 ⚠️ 按时间或请求待核）**，再叠语言/语义路由消除非英语“本地化税”预期额外省 40%–50%。 — S15
    3. 高客单价实时交互反其道而行（5 倍并发冗余）：Cookiy Labs 做 1–2 小时 B2B 用户访谈，最大的成本分母是付给人类受访者的高额报酬，模型费只是零头；为死守 < 1.3 秒 首字语音延迟与北极星指标 insight per minute，对同一请求向同一个模型并发调 5 次、对多家模型也各调 5 次，谁最快返回就用谁。 — B06

1. 上下文的形状重塑与仓库级信噪比门禁#

  • 换掉上下文的形状：Agent 写得出你的私有 JSON，却没法在里面推理：HeyGen 最初在至少 2,000 行私有 JSON 上加视频 Agent，结果两段各 4 行的合法 JSON 渲染出来一段正常、另一段文字完全看不见，Agent 光看 JSON 毫无察觉，就像“让莎士比亚写中文诗”。因为前沿实验室把最大算力砸在训练写代码上，HeyGen 彻底废弃私有 JSON，于 2026 年 4 月开源 HyperFrames，让 Agent 直接写 HTML/CSS/JS 再渲染成 MP4（口述开源半年获约 80,000 star、全球第 2 大 skill、日产约 700,000 条视频，哪怕四周不加功能产品也随基模升级自动增长 ⚠️ 口述与现场视频的全球第 3 / 日产 50 万条略有出入）。 — S19
  • ⚔️ 路线交锋：上下文越完善越好 vs 精心写的上下文反增成本、换仓库反转：
    • 像珍惜内存一样算信噪比：MiniMax 指出模型变强后经常出现 "without skills is better than with skills"，长任务上下文快满时让模型自己把状态写进本地文件做 Hand-off，可能胜过所有精巧设计的压缩算法（S25）。

1. Harness 的加减法与工具调用重构#

  • ⚔️ 路线交锋：模型变强后，Harness 到底该做减法还是做加法？

2. 短命有状态沙箱、百万级 RL 训练沙箱与被推出边界的数据库#

  • 为什么 Kubernetes 不是你的沙箱？（外挂 EBS 的六大硬伤）：Daytona 指出，K8s 为“长期运行、出错自愈的无状态服务”设计，而 Agent 沙箱要的是**“短命但有状态”**。在 K8s 上硬挂外部存储（如 AWS EBS）会踩六个大坑：① 串行起 Pod 吞吐仅 100 个/秒（耗时 1–2s 至几十秒）；② 走网络使 IOPS 从本地 ~500k 暴跌至 50k–60k（跌 10 倍）；③ 挂卷慢 3–19 秒；④ 报错后必须干等 6 分钟才能重挂；⑤ 单节点限挂 25–39 卷，使单机沙箱密度从 110 个直接砍掉 2/3；⑥ 无法多 Pod 共享。专用沙箱靠“停而不删留原节点、热门快照主动扩散、Delta 差量传输”避开冷启动（厂商自测耗时少 36%、波峰负载成本低 2.7 倍 ⚠️ 乙方自报）。 — S10
  • 百万级 RL 后训练沙箱：防 Infra 故障污染 Reward，消灭 80% 思考空等：Google 揭示前沿实验室 RL 训练单任务常达 1,000 task × 16 rollout = 16,000 沙箱并发、训超 150 万个独立镜像。如果沙箱因 Infra 超时或 OOM 崩溃，Reward 函数会误判为模型写代码失败而打出低分，直接污染训练数据与模型权重；且统计百万条轨迹发现沙箱 80% 时间在空等模型生成 CoT，仅 15% 时间在跑代码。Google 开源第一代方案在 4,000 个 CPU 节点上实测 100 万并发连续 8 天零错、12 分钟填满百万预热池、首条指令 P99 < 1 秒（1 万沙箱仅需 512 个网络 Identity）；第二代 Agent Substrate 在等模型思考间隙打压缩快照停掉，靠亚秒级快照恢复瞬间唤醒。 — S16
  • 没人计划过 AI Infra：算存分离防丢成果、千万级隔离小库与 Checkpoint 分支：TiDB 指出容量须按 用户数 × 每用户让 Agent 做多少事 × 历史留多久 算：① 状态表（session snapshot 单条常达 40–80KB，叠加高频 event）涨到 PB 级，逼客户用分布式 SQL 替掉 20+ 分片 DB；② 工作区必须放在独立于沙箱的持久文件系统，防止沙箱回收清理 EBS 时把用户整个项目删光；③ 建站 Agent 平台衍生出上千万个隔离小数据库；④ 长任务单条 Trace 上百 MB/十万步、日写数百 TB，但评估改动不能只看 Trace 或无状态重跑，必须将 Meta + Event + 文件系统 Checkpoint 强绑定，从同一保存现场开独立分支对比。 — S14

3. 管到第 500–2000 个 Agent 的治理转移#

2. 公开榜单为何失灵？四套高 ROI 私有 Benchmark 构建法#

2. 产品交互哲学：工作台 vs 服务窗口，省时间 vs 花/耗时间#

3. 安全权限边界与 Agent 交易经济#

  • 给 Agent 独立 Entra ID 锁死最小权限（防 Harness 工具开关被绕过）：Microsoft Core AI VP 指出，Meta Muse 给 Agent 拟人化身份是为了互动变现，发邮件仍冒用人名（on-behalf-of）；而让 Agent 冒用你极其危险——Harness 里的工具权限开关就像“印度的红绿灯”：你关掉删除工具，它会调 Shell 跑 rm -rf；关掉 Shell，它会自己写一段 Python 程序把文件删光（"The agent will find a way"）。Microsoft 给每个 Agent 发独立的 Entra ID、独立邮箱、Teams 和 OneDrive（在组织架构图里向人汇报），由管理员在身份层按模板授只读等最小权限，无论写 Shell 还是 Python 都越不过去；当 Agent 有了独立身份，将走向不经事先编排的自发协作，需在 OpenEnv 等模拟世界中按安全、合规、正确性三类 Rubric 做隔离测试。 — M02

1. 世界模型四维分类学与“程序管显式状态 + 模型管画面”#

  • 四维分类学与“四向全红灯”反例：World Labs 联合创始人 Christoph Lassner 将世界模型定义为抽象推理（System 2）与感知/行动（System 1）之间的可查询预测接口，按功能（渲染、模拟、规划）× 领域 × 尺度与分辨率 × 覆盖度（Coverage，是否维护当前未观测到的隐藏状态）分类——宽口径下 LLM 和 Google Maps 都算世界模型。现场展示某主流视频模型生成的十字路口漫游视频，镜头绕一圈四个方向红绿灯竟然全都是红灯，直接证明单帧局部视觉一致不等于在后台维护了隐藏状态；因此上层应由 1 个通用 Agent 做 System 2，下层由各带领域世界模型的模块做 System 1（与 S34 下一代家庭机器人架构一致）。 — S18
  • 当 Coding Agent 几十秒纯代码搭出 3D 室内场景：按“可指定性”划界：VAST / Tripo AI 内部群实测发现，新模型下的 Coding Agent 能纯靠写代码在几十秒内搭出带家具尺寸的 3D 室内场景，完全没用原生 3D 模型。团队随即确立新边界：能用文字/代码清晰描述规格的（门位置、开关、计分）交给 Agent 写代码，只能凭肉眼认出但说不清的细节（人脸神似、复杂生物）交给模型从数据中学。为造持久交互世界，采用**“传统游戏灰盒程序显式维护世界状态 + 约 5B 参数模型（约 720p/24fps）读取状态实时渲染画面”（开门、灭火走开再回来仍在，多人异视角状态天然一致；另在自动评测可行走性 Walkability 时，发现 Agent 会自己放椅子或箱子当台阶爬上楼梯钻空子过关**）。 — S27

2. 力觉第一性、独立 PLC 安全隔离与“弃谐波改行星”的可预测硬件#

  • 工业驻场调试成本死穴、力觉第一性与独立 PLC 安全兜底：
    • AiMoga 指出工业产线纯上 VLA 精度不够，用传统视觉每换新品类又要派人长期驻场调试（养不起）；且只看图像看不见接触力、细微滑动和有没有抓稳，“任务要等物理结果验证过才算完成”。其轮式双臂方案从 MES 系统收发工单，补齐力矩与触觉传感，并立下死规矩——工业机器人的安全监督（急停、碰撞保护、运动限制）必须独立于大模型，用 PLC 或 PCB 人工写的安全策略兜底。 — S26
    • 穹彻智能（Noematrix）同样强调具身落地的关键是**“获取一个新能力的成本”（预期半年至 1 年内压到 1 人 2 周工业交付 ⚠️ 预期目标，WAIC 地面清理 Demo 已从 2024 年的 2 人月 / 2000–3000 行代码压到 1 人 1 天）；并指出力觉是操作的第一性输入**——哪怕在不需要力的任务上，后训练加入力的模态也能让模型收敛更快、所需数据更少。 — S31
  • 硬件不追每周一变的模型，而是做成“可预测的稳定接口”（弃谐波改行星减速器）：
    • DYNA 算了一笔节奏账：假设 24 周内模型每周迭代一次有 24 次试错机会，硬件同期只付得起 1–2 次大改。因此硬件不该追着模型改，而该做成缩小 Sim-to-Real 差距的白盒接口（动作模型能预测，反馈模型能信）。为此部件选型全面为可建模性让路：弃用人形主流的谐波减速器（内阻约为行星的 2 倍，且柔性齿轮啮合带历史加载迟滞 Hysteresis 与温漂，极难建模），改用行星执行器——实测双手走圆形轨迹，从仿真迁移到真机的跟踪均方根误差（Tracking RMSE）仅增加 1.3 mm（⚠️ 未给谐波对照数）；同时不加关节力矩传感器，直接靠好建模的行星传动与执行器物理模型由电流估外力（仿真 15N 外力下误差手腕 ~1.39、肘部 ~8 ⚠️ 纯属仿真结果）。 — S32
    • 未来不远在含 1,500+ 零件、21 自由度、22 传感器的家庭机器人 F2 上，严格做好 30Hz 模型输出与 500Hz 底层电机伺服平滑衔接，以及“相机看到半杯水”与“手臂动到该位置”的软硬件时间戳对齐。 — S34

3. 具身数据四路线交锋与 Lance 增量数据构建系统#

  • ⚔️ 路线交锋：具身智能的训练数据到底从哪来？后训练用不用遥操作与仿真？
    1. 路线 A（无本体穿戴采集近 30 万小时，预/后训练全不用遥操作）：穹彻智能不建任何中心化数采工厂，靠全国近 100 个城市、峰值超 1,000 名数采员带无本体穿戴工具进真实场景自采近 30 万小时数据，完全放弃生产级人工标注质检，由 AI 数据管线 T+0 实时反馈好坏；为保数据 pattern 一致，后训练也全部只用无本体方案、明确不用遥操作。 — S31
    2. 路线 B（500+ 真实家庭回流 + 保存“未执行想象候选轨迹”）：未来不远坚持按用户愿付钱的痛点定任务边界（把最难的切辣椒、切肉纳入炒菜闭环），以 1 万小时第一人称 + 3 万小时真机数据为底，在 500+ 真实家庭累计工作超 5 万小时；去掉“人决定何时更新”，模型并行推理多候选时，把**成功、纠正、失败以及“推理时想象过但未实际执行的候选轨迹”**全存盘回流，经 30 轮自进化将 4 项家务平均成功率从 45.4% 提至 86.6%（切菜从 38.2%→68.9% ⚠️ 对应迭代轮数未说明）。 — S34
    3. 路线 C（玻尔兹曼能量地形 + 光量子伊辛机 Real2Real ⚠️）：数耀量生指出单高斯分布拟合多峰动作会取均值撞向两扇门中间的墙；主张只用几十条真机样本反推玻尔兹曼能量地形，把求最低能量点交给 1,000 量子比特光量子相干伊辛机（1–3ms 采样），不经过仿真实现自我改进，宣称突破开源 VLA 基线 8 万 epoch 93.7% 的平台期、仅调隐空间 1.2 万 epoch 达 98%（⚠️ 讲者宣称，展示的 93.7%→98% 实为公开仿真基准结果，现场未公布真机对照数字且微调变量未严格对齐）。 — S30
    4. 路线 D（程序管状态生成人手转机械臂视觉变体）：VAST 尝试用 5B 渲染模型将真实人类演示视频中的人手替换为机械臂批量刷出视觉变体（讲者坦承物理上准不准、对机器人学习有没有用还要实测）。 — S27
  • 机器人数据采集一次、加工无数次，要的是构建系统（Data Build System）而非存储：LanceDB 丁皓指出，每次追加数据、换打标模型或换 Embedding API 都要重算历史数据，必须把原始数据当源码构建：① add column 几乎零开销（只写新文件不重写旧表，原生支持 Git 式分支/Tag）；② 专为机器人设计的 Cell Flag 区分四类空值（夹爪未夹物的有效空、未采集、采集失败、夹爪夹到自己），配稀疏编码将某表从 300+ MB 压到 1 MB（降 300+ 倍）；③ 列绑定 Python 函数做增量 GPU 计算（新增 100 帧只算 100 帧，全算完才原子发布 Snapshot），已支撑 25 PB 工厂视频抽帧训练，Hugging Face LeRobot（⚠️ 推断名）已原生支持 Lance，比其原生格式快 3–5 倍。 — S35
