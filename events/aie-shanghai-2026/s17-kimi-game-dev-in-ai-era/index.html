Life of a Game Developer in AI era

据作者现场录音整理，按讲者脉络转述，不是逐字稿。讲者来自 Kimi（月之暗面），中文演讲，约 10 分钟的快闪场，无问答环节；开场自我介绍那几秒没有录清。

一句话#

AI 能独立跑长程任务以后，做一个可玩游戏原型的时间和成本降到很低，开发者的角色从动手写代码变成定目标、验收和做决定。

论断#

1. 变化的核心原因是长程任务能力#

“有这么多显著的变化的一个核心原因，就是这段时间以来，AI 它在独立去做长程任务的能力上，有了一个突飞猛进的进展”

  • 他说周围很多软件工程师已经不再手写代码，AI 写的代码太多，读不过来。
  • 开场两段 demo：一段是完全由模型自己渲染的动画，模型要理解场景结构并和周围场景交互，开发者只下达一个目标；一段是没有游戏开发背景的同事在纸上画分镜，AI 渲染成 3D 动画。
  • 他用 benchmark 的变化做旁证：long running 类 benchmark 给 agent 一个沙箱，要求它"直接交付一个具体的结果，而不是像以前一样，是用一个 chat 对话框去交付一段代码片段"。测试场景包括让 AI 理解并使用一个小众软件复刻 Flash 游戏《魔塔》，操作具体游戏，操作 Blender。

2. 人管验证和决定，开发执行交给模型#

AI 能独立操作软件界面之后，工程师独立做一个 prototype 的时间降低了很多。

“人类可以就是更多的把他的注意力放在 verify 和做 make decision 的这样的阶段，而把具体的开发和执行委托给我们的模型去去做”

  • 收尾他又说了一次：人扮演的角色更多处在验收和设计的阶段。
  • 他提到很多主流游戏工作室已经把大模型加进生产工作流，没点名。

3. 一个人、约 4 天、约 3000 元 token#

“他们平均呢，每个是花了 4 天时间，花了 3000 块钱的人民币的这个 token 的成本，就可以完成一个以前大家想都不敢想的，由一个人就能完成的这个工作”

  • 他们的展台 demo 了 3 个游戏作品，都是自己的工程师用最新模型做的。
  • 没给比较对象：传统做法要多少人、多少天、多少钱没说，作品是可玩原型还是可发布游戏也没说。

4. 一段视频一周内被做成可玩游戏#

他说随后出现了 video to game 这类技巧：大模型理解一段视频，设计出玩法，把视频变成可以交互的游戏。

  • 抖音上火的"老太太 GTA"本来只是一段视频；放出后大约一个星期，社区就做出可玩版本并在 GitHub 开源，他说玩法"相当的完整"，还能继续加玩法。
  • 用视频生成模型做的游戏"预告片"，也可以用这种做法转成真实可玩的游戏。
  • 做法是给 agent 写一份让它跟随的规则文件（疑为 markdown），有视频就参考视频，有相关代码就参考代码。他说这"非常的简单"。

5. agent 用截图自己找 bug、修 bug#

“AI 它实际上有一个生成了一个 screenshot 的这样一个目录，这个目录呢，实际上是 AI 在通过它的这个多模态的功能，再去观察这个游戏”

  • 他来之前让模型跑了一个项目：给一个游戏立项，解包它的世界地图，做出能航行的玩法，城市也能探索。agent 自己截图、理解 bug、修复，并写了一份完整报告说明怎么发现和修复。他说这样一次迭代能跑得更长。
  • 另一个例子是模仿《过山车大亨》（疑为此作）做的游戏，里面所有景物和游乐设施都是模型自己生成的 3D 模型。

6. 验证一个想法的成本和周期降到很低#

“所有的这些现象表明，现在去验证一个想法的这个成本和周期，在有了大模型之后，都降低到了非常低”

  • 有人在小红书分享的《小王子》游戏。
  • 今年 5 月在某个比赛（疑为 Game Jam）拿冠军的作品。
  • 朋友用 TapTap Maker 做的游戏。
  • 用 AI 把 Switch 上的游戏移植到 iPhone 并适配触屏，例子是《暗黑破坏神 2》。
  • 一位完全没有游戏开发背景、也不是工程师的同事，模仿国产 3A 大作做了一个动作游戏。
  • 每个案例具体怎么做、花了多少没讲；“降低到了非常低"没给具体数字。

存疑#

  • 开场他介绍了"我们的"某个最新模型，型号没听清。
  • 展台作品可能用 Unreal Engine 5 制作，没听准。
  • 4 天、3000 元听着是每个作品的平均值，不是总计，需回放确认。
  • 复刻《魔塔》用的小众软件、long running benchmark 的具体名称、航海类那个游戏的原名都没听清。
