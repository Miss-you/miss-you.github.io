# 图表选择与验收

每次新增或实质修订知识库正文都执行这项检查，无需另等图表请求。先读到原文，判断读者需要比较什么或跟踪什么关系，再选形式；不凭关键词自动改稿，也不规定图表数量、比例或每篇固定模板。

## 按信息关系选形式

| 原文关系 | 优先考虑 | 何时保留原样 |
| --- | --- | --- |
| 多个时间、版本或使用记录并列 | 「时间、版本或记录、变化、来源」四列表格；条件随节点保留 | 单个时间只作背景，或叙事顺序本身有解释作用 |
| 多个对象按相同维度比较，或条件、动作、观察需要对应 | 紧凑表格，让读者沿同一行完成比较；有必要的计算也可逐行对照 | 一两句已能说明，或对象没有共同的比较口径 |
| 分支、并行、汇合、反馈，或需追踪的因果/数据流程 | Mermaid，明确谁做什么、依赖什么、何时继续 | 关系尚未核实，或图只会重复正文而不帮助理解 |
| 简单顺序操作 | 编号清单 | 步骤短、没有分支时无需再画图 |
| 假设与反例、理由与限制、作者经历中的连贯推理 | 段落 | 不为了表格或对称外观切碎论证 |

每个新增图表应能说清省了读者哪一步，例如跨段配对条件与动作、心算差值、记住多个版本，或在脑中重建并行流程。没有明确收益就保留原形式。不要把所有步骤、三项列表或带数字的句子都改成图表。

## 保留事实与证据边界

- 表格各行的来源必须支持该行陈述；保留数字、口径、引文、代码、链接及关键适用条件。条件需要就近看到，不能为缩短单元格移走到读者不易对应的位置；较长解释可放表外。
- 正式发布日期、社区使用记录和作者本次实践是不同证据。不能把检索到的使用记录当成功能发布日期，也不能为了补齐四列编造日期、版本或来源链接。
- 时间戳只支持它实际记录的事件。例如材料只写「19:34 文档最后一次编辑」，就只记最后编辑；即使别处写过已插图、已通读，也不能据此把这些动作绑定到 19:34，更不能称该时点全部验收完成。
- 图中的箭头也是事实表述。只画材料支持的先后、依赖、流向和因果；并行任务不要串行化，只有文档需要的确认不要画成问卷也要等待。条件、假设、未知与未验证状态仍要可见，相关或时间先后不能直接升级为因果。
- 区分路径匹配、实际读取、规则遵守与效果验证，区分静态检查和实网验证；不要因换成图表，把观察或建议写成已验证结果。有英文对应页时，同步共同事实和边界，不要求两种语言机械使用相同排版。

## 手机与实际渲染

- 表格先选少而有用的列，通常两三列即可，时间/版本记录用四列。表头简短，单元格保留比较所需的信息，整段推理和复现细节可移到表外；不能为列数丢条件或来源。必要的宽表可以局部横向滚动，但不应撑出整页。
- 先在实际手机宽度检查中文折行、长路径/命令和来源列。过宽时先分离解释、调整表头和列结构，并检查现有表格样式；不要靠缩小字体或在每个短语后堆手工断行塞满屏幕。样式问题只做必要的局部修复，不扩展为站点重构。
- Mermaid 使用目标站点或阅读器已有的渲染器与标准代码围栏，代码以其能识别的图类型声明开头。发布到博客时，当前实现见博客仓库的 `layouts/partials/extend_footer.html`；本地笔记按实际阅读器核对，不要求复制博客布局或另塞一套渲染器。图类型按关系选择，短标签写明动作与执行者，避免「本人」等歧义；必要时在语义处换行，细节留正文。
- 在目标阅读器或构建后的真实页面中，检查手机与桌面、明暗两种模式的实际呈现，确认生成 SVG、中文不截断、标签能读、箭头和条件正确、并行与汇合清楚，表格可比较且来源可访问。若改了共享样式，还要核对中英文路由及代码块。构建成功不代表浏览器中的 Mermaid 已渲染；外部模块加载失败或未做的检查如实记录。

## 放进写作和验收流程

1. 在底稿或修订记录中简记候选段落、选择的形式及阅读收益；保留原文是正常选择，不把这份内部记录插进公开正文。
2. 将选择、原文、来源与受保护内容交给项目配置的 agy 会话起草或局部修订，继续遵守项目原有写作分工。
3. 事实审稿逐行、逐节点和箭头核对；冷读检查图表是否真的让比较或流程更容易理解，以及有没有与正文重复铺陈。
4. 图表有变化就做上述渲染检查，记录真实结果。prose lint 与 fatigue scan 只提供线索，不能判断关系是否真实，也不能替代这项主动检查。

本约定整理自用户 2026-11-18 的知识库图表盘点及后续规则补充要求。它约束的是表达选择和验收，不要求给每篇知识条目增加图表。
