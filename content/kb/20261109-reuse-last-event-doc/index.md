## 什么时候用

办过一场线下活动，现在要办下一场：时间、嘉宾、话题换了，介绍文档的骨架、到场指引、报名或提问表大体能沿用。

这时可以把上一场的文档链接交给 Agent，再贴一段这次的预告文案。它读完旧文档就知道要哪几节、语气什么样、图片放在哪，你只需要说清楚哪些地方变了。我觉得这比从零描述「我要一份什么样的文档」省事，旧文档里想好的细节也不容易漏，比如场地要先坐电梯到哪一层再转。

## 做法

**给模板，说差异。** 开场消息里放三样东西：上一场的文档链接、这次的预告原文、要几样产出。像「场地不变」这种一句话，就能让 Agent 去旧文档里把整段到场指引和配图搬过来。

**让它开工前一次问清。** 读完参考材料后，它会发现一些自己定不了的事：嘉宾介绍从哪来、文档放哪、问卷收什么。让它把这些攒成一轮提问，你一次答完再开工。

**每样产出各开一个会话。** Claude Code 桌面版里，一个会话可以再开新的会话，新会话各干各的，做完把结果报回来。介绍文档和问卷互不依赖，可以同时做。最先那个会话（下文叫主会话）负责问清需求、分派，最后把问卷链接补进文档并通读核对。

**对外的信息先给你过目。** 嘉宾简介要联网查，查到的东西可能和你手上的说法对不上。让负责文档的会话先把简介草稿和来源发给你，你确认后才写进文档。

## 开场 prompt 的结构

```text
我组织了一场活动，要准备材料。[场地不变 / 其他不变的部分]

[这次的预告原文，原样贴]

我需要：
1. 一份文档，介绍本次活动、嘉宾、如何到达场地。
2. 一个问卷，参考现有的问卷，收集大家对 [话题] 的疑问。

参考文档：[上一场的文档链接]

每件独立的事用一个独立的会话完成，一直到任务完成。
有需要确认的，开始前和我确认，尽量一次问清楚。
```

方括号里换成你自己的内容。我这次没单独给参考问卷的链接，旧文档末尾有报名表，Agent 自己找到了原表。

## 我的实践

2026 年 11 月 9 日，我要给一场周六的线下分享会准备介绍文档和问卷。嘉宾两位：一位基金公司的投资总监讲市场和 AI，一位科技媒体的作者讲 AI 全景。场地和 6 月那场一样。我在 Claude Code 桌面版里发了上面那种结构的开场消息，附上那一场的飞书文档链接。

主会话先读了旧文档和旧报名表（7 个字段），然后一轮问了我 4 件事：嘉宾资料从哪来、第二位嘉宾要不要写名字、问卷收什么、现场形式怎么写。问卷这一项我没选它推荐的报名和提问合一，只收疑问，报名照旧加我微信进群。现场形式我补了一句：两场分享加自由交流，不排细流程。

答完后它开了两个会话，一个做问卷，一个写文档。问卷那边约 3 分钟建好，自己提交了一条测试记录确认能填，再把它删掉。文档那边联网查嘉宾时发现，第一位嘉宾公开报道里的头衔是某个部门的投资总监，和我预告里写的头衔不一样。第二位嘉宾的两个身份在公开网页上查不到。文档会话把这两处列出来等我决定。头衔我选了公开报道的写法。第二位的身份是我自己给的，主会话转告它照写。

旧文档里有 5 张带箭头标注的到场指引图，文档会话把它们下载下来，按原顺序插进新文档。主会话最后读了一遍成品，逐项核对日期、星期、时间、地点、费用、图片顺序和问卷链接。

按会话和文档的时间戳，北京时间 19:11 开始，19:20 两个会话启动，19:34 文档最后一次编辑。中间我回答了两次：开工前那一轮，和嘉宾头衔那一次。

两处没做好：

- 指引图是按原尺寸插入的，旧文档里缩小过，新文档在手机上可能偏大。这一点没有在飞书里实际看过。
- 做问卷的会话查表时，在本地仓库根目录留下两个空的导出文件，删除被权限拦下，最后要我手动删。

## 适用条件

前提是上一份材料还在，Agent 也能读到它。我这次用的是飞书的命令行工具 lark-cli，以我本人身份读写。头一回办、没有可参考的文档时，开场消息就得把结构写全，省不了这一步。

两件事放在一个会话里串行做要多久，我没有比较过。

需要对外发布的内容，比如嘉宾头衔和简介，Agent 查到的只能当草稿，要自己确认后再写进去。
