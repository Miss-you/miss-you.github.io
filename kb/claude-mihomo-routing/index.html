官方要求与可选共享主机#

根据 Claude Desktop 网络要求 与 Claude Code 网络配置，官方 Desktop 清单明确包含 claude.app 及动态 livepreview 子域；结合网络配置文档中的 anthropic.com、claude.ai、claude.com、claudeusercontent.com、claudemcpcontent.com 后缀，可覆盖 API、登录、下载、桥接与 MCP 小组件。

claude.dev 用于开发者博客，clau.de 与 claudemcpclient.com 作为扩展覆盖纳入，anthropic.skilljar.com 保留为辅助内容域名。GitHub 上的社区列表仅用于发现候选域名，并非独立证据，不宜将额外的社区域名全部视为必需。参考：Claude Academy 开发者博客入口、v2fly anthropic 列表、MetaCubeX anthropic.list。

browser-intake-us5-datadoghq.com 与 http-intake.logs.us5.datadoghq.com 属于可选遥测，改用两条精确 DOMAIN 规则，并保留 cdn.usefathom.com 精确规则（参见 Claude Code 网络要求）。为避免误伤非 Claude 流量，移除 datadog、sift 关键词及 Sentry、Statsig、Intercom 共享后缀；GitHub、Google Storage、npm 等共享主机沿用原来的通用策略。

Claude 身份验证说明 确认 Persona 为 Claude 的身份验证合作方。本示例从 Persona 安全与域名清单 中启用了 4 个主机（inquiry.withpersona.com、cdn.withpersona.com、sdk.withpersona.com、miniapp.withpersona.com），但它们只是通用共享主机，不能推导为 Claude 必需。

入站 CIDR 方向与匹配顺序#

IP 兜底规则采用官方发布的入站地址段 160.79.104.0/23、153.61.224.0/22 与 2607:6bc0::/48（均附加 no-resolve），替换范围更宽的 IPv4 /21（实为 Anthropic 出站范围）与旧 IPv6 /32；IP-ASN,399358 默认注释，按需启用。参考：Anthropic API IP 地址文档。

依据 Mihomo 规则配置文档，Mihomo 按自上而下的顺序匹配规则，因此整段 Claude 规则必须置于可能先命中的通用规则及兜底 MATCH 之前。no-resolve 不会主动触发 DNS 查询，但若前置规则已经触发过 DNS 解析，IP 规则仍可命中。

验证状态与实网排查#

当前已完成静态配置核对：YAML 语法可正常解析、Claude 策略组存在（本次仅保留一个候选，其他策略组与节点定义保持原样）、24 条启用的规则位于原规则块位置、非 Claude 配置未变。尚未验证运行中客户端的重新加载与实网出口。

实网验收需按顺序执行以下检查：

  1. 重载配置：在运行中的 Mihomo 客户端重新加载配置文件，确认无报错或策略组缺失提示。
  2. 分场景核对连接日志：在客户端连接日志中核对实际选中的出站节点与命中的规则策略。发起网页对话可核对 claude.ai 等核心域；普通 CLI 请求只能确认 API 路由，登录与下载链路需在后续实际使用中分别核对日志，不建议为测试而专门退出登录；如使用 Desktop，可按需触发预览以核对 claude.app 及动态 livepreview 子域。
  3. 排查本地链路：若 CLI 或桌面端流量未出现在 Mihomo 日志中，检查终端代理环境变量（HTTP_PROXY / HTTPS_PROXY）或系统 TUN 模式接管状态。
